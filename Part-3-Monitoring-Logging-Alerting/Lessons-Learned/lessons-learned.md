# Lessons Learned

## Project Overview

This project demonstrates how Google Cloud Monitoring and Cloud Logging can be integrated with Kubernetes workloads to achieve centralized monitoring, log analysis, and automated alerting.

---

## Key Learnings

### Google Kubernetes Engine (GKE)

- Created and managed Kubernetes clusters.
- Deployed containerized applications.
- Exposed applications using LoadBalancer services.

---

### Artifact Registry

- Created Docker repositories.
- Tagged Docker images.
- Stored container images securely.

---

### Cloud Logging

- Collected logs from Kubernetes workloads.
- Used Logs Explorer to analyze application behavior.
- Filtered logs based on severity levels.

---

### Log-Based Metrics

- Converted application logs into monitoring metrics.
- Created custom metrics from HTTP error events.

---

### Cloud Monitoring

- Visualized application metrics.
- Monitored application health.
- Observed resource utilization.

---

### Alert Policies

- Configured log-based alert policies.
- Connected notification channels.
- Automated incident generation.

---

### Notification Channels

- Configured email notifications.
- Validated alert delivery mechanisms.

---

## Skills Gained

- Kubernetes Administration
- Container Deployment
- Artifact Registry Management
- Cloud Logging
- Cloud Monitoring
- Log-Based Metrics
- Alert Policy Configuration
- Incident Monitoring
- Cloud Observability

## Challenges Faced

- Configuring Kubernetes services.
- Waiting for external LoadBalancer IP allocation.
- Creating accurate log filters.
- Validating alert conditions.
- Generating application errors for testing.

---

## Outcome

Successfully implemented an end-to-end cloud monitoring solution capable of:

- Deploying applications
- Collecting logs
- Creating custom metrics
- Monitoring workloads
- Triggering alerts
- Managing incidents

This project strengthened practical knowledge of Google Cloud observability and production monitoring.
